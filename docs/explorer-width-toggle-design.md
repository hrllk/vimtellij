# Design: 반복 가능한 Snacks Explorer 폭 토글

Mode: Builder

## Problem Statement

`lua/config/snacks/explorer.lua`의 `=` 키는 현재 explorer 폭을 `40%`와 `50%` 사이에서만 전환한다. 원하는 동작은 한 picker 안에서 다음 사이클을 반복하는 것이다.

`default → 30% → 40% → 50% → default`

여기서 `default`는 explorer를 처음 열었을 때 Snacks가 계산한 실제 폭이며, explorer를 닫는 상태가 아니다.

## What Makes This Useful

한 키로 explorer를 좁게 보거나 넓게 볼 수 있고, 마지막에는 사용자가 처음 보던 레이아웃으로 정확히 돌아갈 수 있다. `=`를 여러 번 눌러도 같은 사이클이 반복되어 별도 리셋 키가 필요 없다.

## Constraints

- 변경 대상은 `lua/config/snacks/explorer.lua`로 한정한다.
- `D` diff 동작, `<leader>e` 키맵, explorer topology, dashboard refresh는 유지한다.
- 기존 `min_width = 40`을 유지한다.
- 퍼센트 폭은 picker 레이아웃의 `width` 값으로 적용한다.
- 좁은 터미널에서는 `min_width` 때문에 실제 폭이 30%보다 커질 수 있다.

## Premises

1. 상태는 picker 인스턴스별로 관리해야 한다.
2. 첫 `=` 입력 직전에 `picker.resolved_layout.layout.width`를 저장하면 현재 default를 정확히 복원할 수 있다.
3. `50%`에서 default로 돌아갈 때 상태를 삭제하면 동일 picker에서 다음 사이클을 다시 시작할 수 있다.
4. Lua weak-key table을 사용하면 picker가 사라진 뒤 폭 상태가 남지 않는다.

## Approaches Considered

### Approach A: Picker별 weak-key 상태 테이블

액션 함수 바깥에 picker를 키로 사용하는 weak-key table을 두고 `{ default_width, step }`을 저장한다. 첫 단계에서 기본 폭을 캡처하고, 30/40/50을 순서대로 적용한 뒤 default에서 저장된 폭을 복원하고 항목을 삭제한다.

- Effort: S
- Risk: Low
- Pros: default를 정확히 복원하고 picker 수명과 상태 수명이 자연스럽게 맞는다.
- Pros: Snacks picker 객체에 임의 필드를 추가하지 않는다.
- Cons: 작은 상태 테이블과 단계 전이 로직이 필요하다.
- Reuses: 기존 `picker.resolved_layout`, `picker:set_layout`, `picker.list.win:focus`, dashboard refresh.

### Approach B: Picker 객체에 상태 필드 저장

`picker` 객체에 기본 폭과 현재 단계를 직접 기록한다.

- Effort: S
- Risk: Low/Med
- Pros: 액션 함수에서 상태를 찾기 쉽고 코드가 짧다.
- Pros: 별도 모듈 상태가 필요 없다.
- Cons: Snacks 내부 객체에 사용자 필드를 추가하므로 이름 충돌과 내부 변경에 민감하다.
- Reuses: 기존 layout 갱신 흐름.

### Approach C: 현재 폭만 보고 다음 폭 계산

현재 폭이 30/40/50인지 비교해 다음 값을 고른다.

- Effort: S
- Risk: Med
- Pros: 저장 상태가 없어 구현량이 가장 작다.
- Cons: 초기 default가 30/40/50과 같을 때 구분할 수 없다.
- Cons: Snacks 기본 폭을 정확히 복원할 수 없어 요구사항을 완전히 만족하지 못한다.

## Recommended Approach

Approach A를 권장한다. 사용자가 선택한 “처음 default 폭 저장 후 복원”을 정확히 구현하면서 변경 범위가 한 파일에 머문다. 상태 전이는 `default → 0.3 → 0.4 → 0.5 → default`로 명시하고, default 복원 시 상태를 제거해 무한 반복이 가능하도록 한다.

각 단계에서 공통 layout 생성 경로를 사용한다. `source = "explorer"`, `preset = "sidebar"`, `preview = false`, `min_width = 40`과 focus 및 dashboard refresh 동작은 그대로 유지한다.

## Open Questions

- Snacks가 터미널 resize 중 `picker.resolved_layout.layout.width`를 갱신하는 시점은 확인이 필요하다. 현재 설계는 “첫 입력 시점의 실제 default를 복원”한다.
- 터미널 폭이 충분히 작아 30%가 `min_width = 40`에 걸릴 때는 설정값과 실제 폭이 다를 수 있다. 이는 기존 최소 폭 정책을 유지한 결과다.
- 현재 저장소의 `scripts/check`가 Lua syntax와 isolated config load를 검증하지만, 실제 Snacks picker 상호작용 테스트는 제공하지 않는다.

## Success Criteria

- 첫 입력 후 폭 설정은 30%다.
- 이어지는 입력은 40%, 50%를 순서대로 적용한다.
- 네 번째 입력은 첫 입력 전의 default 폭을 복원한다.
- 다섯 번째 입력부터 같은 사이클이 반복된다.
- 각 단계 후 explorer 목록에 focus가 남고 dashboard refresh가 실행된다.
- `D`와 `<leader>e` 동작에 변화가 없다.
- `scripts/check`가 통과한다.

## Next Steps

2. 공통 layout 적용과 상태 초기화를 한 흐름으로 유지한다.
3. `scripts/check`를 실행하고, 가능하면 실제 Neovim에서 `=`를 다섯 번 눌러 폭 순서를 확인한다.

## What I noticed about how you think

- 처음에는 `30% → 40% → 50% → off`를 제안했지만, 곧바로 “닫힘이 아니라 default”라고 사용자가 보는 상태를 더 정확히 정의했다.
- `default`를 단순한 고정 폭이 아니라 처음 열었을 때의 실제 값으로 복원하도록 선택했다.
- 구현 방식에서도 가장 짧은 코드보다 picker별 상태 수명과 반복 가능성을 우선했다.
